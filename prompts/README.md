# prompts

Системные промпты узлов графа Agent Forge. Промпты вынесены из кода и версионируются — правило проекта (см. корневой CLAUDE.md). Каждый файл — контракт узла: роль, вход, поведение, выход.

## Состав

| Файл | Узел | Назначение |
|------|------|------------|
| `planner.md` | `planner` | Декомпозирует техзадачу в пошаговый план (`Plan`). Код НЕ пишет. |
| `coder.md` | `coder` | Генерирует Python-код по плану и контексту (`GeneratedCode`); на повторной итерации учитывает feedback ревьюера. |
| `reviewer.md` | `reviewer` | Ревьюит код по плану, выносит вердикт `pass`/`fix` с замечаниями (`ReviewVerdict`); замыкает reflection-петлю. |

## Конвенции

### Структурированный вывод
Узлы используют `.with_structured_output(Schema)`. JSON-схема навязывается кодом, поэтому в промптах она дословно НЕ дублируется — промпт описывает роль, критерии качества и поведение, а раздел «Выход» лишь напоминает, что именно вернуть. Схемы: `Plan`, `GeneratedCode`, `ReviewVerdict` (в `app/schemas/`).

### Плейсхолдеры
Подстановки в двойных фигурных скобках, подставляются кодом узла при сборке сообщения:
- `{{ user_task }}` — исходное ТЗ (planner);
- `{{ plan }}` — план от Planner (coder, reviewer);
- `{{ retrieved_context }}` — контекст из RAG, может быть пустым (coder);
- `{{ reviewer_feedback }}` — обратная связь ревьюера, пустая на первой итерации (coder);
- `{{ generated_code }}` — код от Coder (reviewer).

### Изоляция ввода
Пользовательские данные (ТЗ, код, контекст) обёрнуты в теги (`<task>`, `<plan>`, `<code>` и т.п.) и явно помечены как данные, не как инструкции — защита от prompt injection. При подключении в код подставляй значения строго внутрь этих тегов.

### Версионирование
Версия — в шапке каждого файла:

```
# <node>
version: MAJOR.MINOR.PATCH
node: <имя узла графа>
model: GigaChat-2-Max
```

- PATCH — формулировки, опечатки, уточнения без смены поведения;
- MINOR — новые правила/критерии, обратно совместимые;
- MAJOR — смена роли, контракта или формата вывода.

Заметное изменение промпта фиксируй бампом версии и упоминай причину в коммите — это страхует eval-gate в CI от молчаливой регрессии.

### Целевая модель
Все промпты написаны под **GigaChat-2-Max**: коротко и директивно, по-русски, однозначные формулировки, без избыточного chain-of-thought. При смене модели проверь промпты повторно — поведение чувствительно к формату.
